## How validators agree

The leader asks its model and returns one string, the three labels in order, such as `PASS,FAIL,PASS`. Each validator asks its own model the same prompt and agrees only when its own three labels are exactly the leader's. Nothing else is compared and nothing else is stored from the model, so agreeing on the labels is agreeing on the verdict.

The pass is then computed in contract code: at least the gate's pass mark of PASS labels. What happens next (PASSED, RETRY, LOCKED, the cooldown and the lock) is the contract's rule, never the model's.

An answer that cannot be read (not JSON, the wrong number of labels, or a label outside PASS and FAIL) is retried once, then fails the round. It never becomes a label.
